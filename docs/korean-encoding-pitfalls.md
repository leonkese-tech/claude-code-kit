# 윈도우에서 한글 스크립트를 짤 때 밟는 인코딩 함정

콘솔·`.bat`·파이프·스케줄러가 각각 다른 인코딩을 씁니다. 한 곳에서 됐다고 다른 곳에서 되지 않으니, **실제로 돌 자리에서** 확인하세요.

| 어디서 | 증상 | 해야 할 것 |
|---|---|---|
| 파이썬 표준출력 | `—`, `⚠` 하나에 `UnicodeEncodeError`(cp949) | 스크립트 첫머리에 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` |
| 자식 프로세스 파이프 | `.bat`으론 되는데 부모 프로세스에서 돌리면 죽는다 | 부모가 자식 환경에 `PYTHONIOENCODING=utf-8`을 넣어 준다 |
| `subprocess(text=True)` | cp949로 풀다 리더 스레드가 죽어 `stdout`이 `None`이 된다 | 바이트로 받아 직접 디코딩한다(utf-8 → 콘솔 코드페이지 → replace 순). `errors='replace'`만으로 때우면 죽지는 않지만 한글 오류가 `����`로 남아 원인을 못 읽는다 |
| HTTP 헤더 | 요청이 아예 안 나간다(`latin-1` 오류) | 헤더 값은 영문만. 한글은 본문에 |
| `.bat` 런처 | 한글 로그가 깨진다 | 첫 줄에 `chcp 65001 >nul` |
| `.bat`을 LF로 저장 | cmd가 줄을 뭉개 엉뚱한 줄만 실행한다(로그 0바이트) | CRLF로 저장한다. 스케줄러 런처는 특히 |
| `.ps1` | 한글이 깨지고 파일명이 `?`로 망가진다 | UTF-8 **BOM**으로 저장한다(Windows PowerShell 5.1은 BOM이 없으면 ANSI로 읽는다) |
| Bash heredoc | 백슬래시 시퀀스가 진짜 개행·제어문자로 박힌다 | 파일 쓰기는 편집기나 에이전트의 파일 쓰기 도구로 한다 |
| Git Bash 인자 | `/Create`가 `C:/Program Files/Git/Create`로 바뀐다 | `schtasks` 같은 건 PowerShell로 실행한다 |
| `python -c` 인라인 | 한글 경로·문자열에서 깨진다 | 스크립트 파일로 저장해 실행한다 |
| 엑셀 평문 추출 | 값에 제어문자가 섞여 문자열 비교가 빗나간다 | 비교 전에 제어문자를 제거한다 |

스케줄러(서비스 컨텍스트)로 도는 경로가 사용자 세션과 가장 자주 다릅니다.
