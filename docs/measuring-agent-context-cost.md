# Claude Code 컨텍스트 비용, 자기보고 말고 대조군으로 재세요

**TL;DR (EN):** Don't ask a model what its context contains, and don't benchmark a tool against something you never actually do. Build two probes that differ in exactly one thing and compare the sub-agent token counts. A "30x saving" against reading whole files turned into −3.3% against the grep/sed workflow the team really used.

관측 몇 건이 전부이고 한 번씩만 잰 값입니다. 숫자보다 **재는 방법**을 가져가세요.

## 1. 모델에게 "뭘 싣고 있어?" 라고 묻지 마세요

하위 에이전트 둘을 비교하면서 자기보고를 믿었더니 이런 모순이 나왔습니다.

- 에이전트 A: "도구 41개", 에이전트 B: "도구 30개"
- 그런데 토큰 차이는 고작 2,500 → 11개 차이치고 너무 작다

원인은 간단했습니다. 둘 다 `tools: *` 라 도구 집합이 같았고, 41과 30은 모델이 지어낸 숫자였습니다. 갯수 세기도 틀립니다.

### 대조군으로 재는 법

`tools:` 줄만 다르고 나머지는 같은 에이전트 정의 두 개를 만듭니다.

| 프로브 | 도구 | 같은 프롬프트로 잰 서브에이전트 토큰 |
|---|---|---|
| probe-one | 1개 | 73,704 |
| probe-many | 19개 | 93,893 |

차이 20,189 ÷ 18 ≈ **도구 하나당 약 1,100~1,200 토큰**이었습니다(이 환경의 값. 도구 정의 크기에 따라 달라집니다).

주의할 점:

- 프로젝트 지침 파일(`CLAUDE.md`)은 **세션 시작에 스냅샷**됩니다. 고친 그 세션에서는 전후를 못 잽니다. 새 세션에서 재세요.
- 반대로 `.claude/agents/*.md` 정의는 세션 도중에도 반영됩니다. 이 비대칭을 이용하면 "정의에만 있고 스냅샷엔 없는 값"을 물어서 반영 여부를 검증할 수 있습니다.
- 커스텀 에이전트는 지침 파일을 **물려받습니다.** 규칙을 전문가 정의로 "옮기기만" 하면 절감이 0입니다. 지침 파일에서 **실제로 지워야** 줄어듭니다.

## 2. 지침을 전문가로 쪼갠 결과 (한 번 잰 값)

지침 파일 하나를 도메인별 전문가 에이전트 십여 개로 나누고 본문에서는 규칙을 지웠더니, 지침 파일이 **약 절반**으로 줄었습니다. 옮긴 규칙은 기계로 전건 대조해서 유실이 없는지 확인했습니다. 손으로 옮긴 규칙의 유실이 가장 흔한 사고라서 대조 단계를 빼지 마세요.

## 3. "관련 절만 주입" 은 재현율이 문제입니다

지침을 통째로 싣는 대신 지시문에 맞는 절만 주입하는 안을 실제 과거 지시 수십 개로 재 봤습니다.

| 설정 | 재현율 | 절감 |
|---|---|---|
| 작은 예산 | 약 78% | 과반 |
| 예산 확대 | 약 87% | 절감이 거의 사라짐 |

"작게 싣고 다 맞히는" 조합은 없었습니다. 놓친 유형은 셋입니다.

1. "~는 전문가에게 맡긴다" 같은 위임 절 (본문이 짧아 밀림)
2. 해법에 쓰이는 규칙인데 지시문에는 그 낱말이 없는 경우 ("알림이 너무 많아" → 알림 중복 제거 규칙)
3. 여러 주제가 섞인 지시의 뒤쪽 주제

그래서 이 도구는 주입기가 아니라 **계량기**로만 씁니다. 규칙을 옮기기 전에 "옮긴 뒤에도 검색으로 찾아지는가"를 확인하고, 안 잡히면 옮기지 않습니다. 못 실은 규칙은 같은 사고를 다시 부르고, 22% 누락은 아낀 토큰보다 비쌉니다.

## 4. 기준선을 "하지 않는 행동"으로 잡지 마세요

코드 지도 도구(AST로 뼈대를 뽑아 큰 파일을 통째로 읽지 않게 하는 도구)를 만든 개발자의 측정은 "필요한 파일을 통째로 읽기" 대비 **30배 절감**이었습니다. 튜닝에 쓰지 않은 새 질문 6개로 에이전트 대조군 A/B를 돌렸더니:

| | 도구 사용 | 대조군(grep → sed -n) |
|---|---|---|
| 토큰 | 기준 | **−3.3%** |
| 시간 | | +44% |
| 정확도 | 6/6 | 6/6 |

대조군도 이미 `grep -n` 으로 위치를 찾고 `sed -n` 으로 필요한 줄만 읽고 있었기 때문입니다. 기준을 실제로 하지 않는 행동으로 잡으면 어떤 도구든 좋아 보입니다.

### 새 도구를 채택하기 전 체크

1. 대조군은 **지금 실제로 하는 방식**.
2. 표본은 튜닝에 쓰지 않은 것(hold-out).
3. 지표는 토큰·도구 호출·시간·**정확도**를 함께.
4. 결과가 기대와 다르면 변경 기록의 제목까지 고쳐 남기기.

## 한계

- 모두 한 환경에서 한 번 잰 값입니다. 모델·버전·도구 정의가 바뀌면 달라집니다.
- 표본이 작습니다(지시 수십 개, 질문 6개). 방향을 보는 용도입니다.
