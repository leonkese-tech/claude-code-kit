# 실패한 실험 두 가지: 제로샷 라우터, 규칙 미세조정

**TL;DR (EN):** (1) A multilingual encoder classifier used zero-shot as a cloud-vs-local router scored below "predict the majority class" on Korean work e-mail. (2) Fine-tuning a 27B local model on a rules Q&A set raised the knowledge score slightly but collapsed code-edit tasks from 9/9 to 4/9 and made the model answer wrongly with confidence. Both are single runs on small, private data; read them as warnings, not benchmarks.

## 1. 제로샷 분류기를 라우터로 쓰기 — 접음

**하려던 것.** 공개된 다국어 인코더 분류기(mmBERT 기반)를 "이 요청은 클라우드 모델이 필요한가, 로컬로 충분한가"를 가르는 라우터로 쓰는 것. 미세조정 없이.

**결과.**

| 지표 | 값 |
|---|---|
| 한국어 업무 메일 분류 정확도 | 0.327 |
| "전부 한 클래스로 찍기" 기준선 | 0.500 |
| 라우팅 판별 AUROC | 0.40 ~ 0.56 |

본문 길이만 보는 단순 규칙보다도 나빴습니다. 모델 작성자도 "미세조정을 전제로 한다"고 적어 두었습니다. 즉 모델 설치나 사용법의 문제가 아니라 체크포인트가 이 용도에 맞지 않았습니다.

**교훈.**

- 기준선으로 "다 찍기"와 "본문 길이"를 같이 재세요. 정확도 숫자만 보면 33%가 나쁜지 알 수 없습니다.
- 다시 볼 조건은 하나입니다. 사람이 단 라벨 수백 건으로 미세조정한 뒤, 실제 트래픽을 흘려 보는 shadow 측정으로 다시 재는 것.
- 같은 모델을 다시 받아서 처음부터 재는 낭비를 막으려고 결론과 이유를 남겨 둡니다.

**덤 발견.** 같은 분류를 7~14B급 로컬 모델에 시켰더니 클라우드 소형 모델의 판정과 0.70 일치하고 4.6배 빨랐습니다. 사람 검수 표본으로 정확도를 확인한 다음에 로컬 우선으로 바꿀지 정하기로 했습니다(결정 대기).

## 2. 규칙 지식을 가중치에 굽기 — 코드 수정 능력이 반토막

**하려던 것.** 로컬 27B 모델에 프로젝트 규칙 문서를 미세조정으로 넣어서, 매번 문맥에 규칙을 싣지 않아도 되게 하는 것.

**실험.** 규칙 문서에서 만든 문답 3,378개를 2회독했습니다(846 스텝, 약 189분).

| | 전 | 후 |
|---|---|---|
| 규칙 지식 점수 | 14.9 | 16.5 (+1.6) |
| 코드 수정 과제 통과 | 9/9 | **4/9** |
| 모르는 것에 대한 태도 | "모른다" | 틀린 답을 단정 |

지식은 조금 올랐는데 기존 능력이 무너졌고, 모르던 걸 모른다고 하던 모델이 자신 있게 틀리게 됐습니다. 교체 조건(지식 +3 이상 **그리고** 기존 과제 유지)이 막아 줘서 운영 모델은 그대로 두었습니다.

**교훈.**

- 규칙·사실은 가중치가 아니라 **문맥**으로 넣으세요(검색 + 교훈 주입). 바뀌는 사실을 가중치에 구우면 고치기도 어렵습니다.
- 교체 조건을 "새 능력이 오른다"가 아니라 "새 능력이 오른다 **그리고** 기존 과제가 유지된다"로 거세요. 이 게이트가 없었다면 올라간 점수만 보고 바꿨을 겁니다.
- 미세조정을 다시 시도한다면 "문답"이 아니라 **도구를 쓰는 과정이 담긴 실제 검토 표본**이 쌓인 뒤입니다. 파이프라인은 끝까지 도는 것까지 확인해 뒀습니다.
